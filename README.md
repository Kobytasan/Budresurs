# «Прометей» — онлайн-магазин і тестовий кошик

Навчальний сайт українського продуктового магазину: React/Vite інтерфейс, каталог, пошук, кошик, оформлення замовлень і рольовий робочий кабінет. Сервер API та збереження даних працюють на Python і SQLite.

## Запуск на Windows

1. Встановіть Node.js і Python.
2. Відкрийте PowerShell у папці проєкту та встановіть залежності frontend:

   ```powershell
   npm install
   ```

3. Зберіть React-застосунок:

   ```powershell
   npm run build
   ```

4. За бажанням задайте власний пароль директора **перед першим запуском**:

   ```powershell
   $env:PROMETEY_ADMIN_PASSWORD = "Ваш-надійний-пароль"
   ```

5. Запустіть Python API та вебсервер:

   ```powershell
   python server.py
   ```

6. Відкрийте магазин: <http://127.0.0.1:8000>. Кабінет команди: <http://127.0.0.1:8000/admin>.
7. Щоб завершити роботу локального сервера, натисніть `Ctrl+C`.

Для frontend-розробки відкрийте два вікна PowerShell: в одному запустіть `python server.py`, в іншому — `npm run dev`. Vite відкриє адресу, яку покаже термінал (типово <http://127.0.0.1:5173>) і проксуватиме `/api` до Python-сервера на порт 8000.

Покупці створюють особистий кабінет на сторінці `/account`. Після входу оформлені замовлення зберігаються в історії профілю; для кожного можна переглянути та надрукувати квитанцію або зберегти її у PDF із вікна друку. Гостьове оформлення замовлення також доступне, але такі покупки не прив’язуються до профілю.

Під час першого запуску база створюється у `data/prometey.db`, а товари завантажуються з окремих файлів каталогу в `catalogs/`. За замовчуванням для локальної демонстрації створюється директор `director` із паролем `PrometeyDemo2026!`. Пароль директора зберігається у базі у вигляді PBKDF2-хешу, не у відкритому вигляді. Після створення бази змінна середовища не змінює вже наявний пароль.

У локальному деморежимі внизу сторінки входу команди відображаються всі профілі працівників із кнопкою швидкого входу. Він дає змогу переглянути кожен кабінет без пароля; список показує лише ім’я, логін та роль — пароль не передається. Цей режим працює лише при локальному запуску на `127.0.0.1`, `localhost` або `::1`; для запуску в публічній мережі вимкніть швидкий вхід:

```powershell
$env:PROMETEY_DEMO_MODE = "0"
```

## Розгортання на хостингу

Щоб магазин працював без запуску на вашому комп’ютері, зберіть frontend командою `npm ci && npm run build`, а потім завантажте файли проєкту разом із папкою `dist/` на хостинг Python-застосунків. Команда запуску — `python server.py`; вона обслуговує зібрані сторінки та API з одного джерела, тож маршрути React працюють при прямому відкритті й оновленні сторінки. Хостинг запускатиме процес автоматично; локальний сервер вашого комп’ютера для цього не потрібен. Сервер слухає адресу й порт зі змінних середовища:

| Змінна | Значення для хостингу |
|---|---|
| `PROMETEY_HOST` | `0.0.0.0`, щоб хостинг міг приймати інтернет-запити |
| `PORT` | Порт, який надає хостинг; якщо він не заданий, використовується `PROMETEY_PORT` або `8000` |
| `PROMETEY_DB_PATH` | Повний шлях до SQLite-файлу на постійному диску хостингу, наприклад `/var/data/prometey.db` |
| `PROMETEY_ADMIN_PASSWORD` | Пароль директора довжиною щонайменше 12 символів, заданий у налаштуваннях секретів хостингу |
| `PROMETEY_DEMO_MODE` | `0`, щоб вимкнути локальний швидкий демовхід |
| `PROMETEY_COOKIE_SECURE` | `1`, якщо HTTPS завершується на проксі й він не передає `X-Forwarded-Proto: https` |

Важливо: SQLite-файл зберігається на сервері, але хостинг має надати **постійний диск** і не видаляти його під час перезапуску чи нового розгортання. Якщо залишити файл у тимчасовій папці або використовувати кілька копій застосунку на різних серверах, дані можуть зникнути або розійтися. Поточна реалізація розрахована на один екземпляр сервера з постійним диском. Перший запуск на хостингу створить нову базу, завантажить товари з `catalogs/` та створить директора; локальний файл `data/prometey.db` до проєкту не входить і автоматично на хостинг не переноситься.

Для реального використання увімкніть HTTPS на хостингу й задайте секрети у його панелі, а не у файлах проєкту. Перед запуском на публічній адресі `PROMETEY_ADMIN_PASSWORD` обов’язковий: без нього або якщо він коротший за 12 символів сервер відмовиться стартувати, щоб не створити директорський доступ із демонстраційним паролем. Перед публічним запуском також перевірте, що хостинг підтримує постійний диск для SQLite. Вбудований HTTP-сервер призначений для цього навчального застосунку; для справжнього магазину потрібні окремо налаштований production-сервер, HTTPS і резервні копії.

## Ролі та доступ

| Роль | Доступ |
|---|---|
| Директор | Фінанси, товари, працівники, історія статусів, постачальники й звернення підтримки; замовлення з контактами покупців |
| Бухгалтер | Вкладка фінансів, показники, журнал сум і статусів оплати; без контактів покупців, складу чи керування командою |
| Працівник складу | Вкладка товарів, постачальники, залишки й ціни; без фінансів і даних покупців |

Додайте колегу у вкладці працівників кабінету директора: задайте ім’я, логін, посаду й тимчасовий пароль щонайменше з 12 символів. Кожен працівник може самостійно встановити статус «На роботі», «Вихідний», «У відпустці» або «Кінець робочого дня». Директор бачить історію змін і тривалість від останнього початку роботи до завершення дня. Директор може змінити роль або вимкнути/відновити доступ; вимкнення завершує активні сеанси працівника. Система не дозволяє вимкнути останнього директора чи його власний обліковий запис. Директор керує довідником постачальників, а працівники з доступом до товарів можуть обрати постачальника для кожного продукту.

Покупці можуть обрати улюблені товари, які показуються у вкладці «Улюблене» на сторінці `/products`. Список улюбленого та кошик наразі зберігаються у браузері; профілі, замовлення, залишки, постачальники, статуси працівників і звернення підтримки — у серверній базі SQLite. Каталог оновлює залишки приблизно кожні 15 секунд і позначає товари з нульовим залишком як недоступні.

Головна сторінка `/` містить інформацію про магазин. Каталог розміщений на `/products`, інформація про компанію — на `/about`, форма підтримки — на `/support`, кабінет покупця — на `/account`, а кабінет команди — на `/admin`. Місто доставки можна вибрати з переліку Київ, Львів, Одеса, Дніпро, Харків, Вінниця, Черкаси та Полтава; цей перелік є демонстраційним, тому доступність і умови доставки потрібно перевірити для кожного міста окремо. Реальні адресу, телефон і графік компанії не задано, тому сайт не вигадує ці контактні дані.

## Структура

- `src/App.tsx` — маршрути публічних сторінок і кабінету команди.
- `src/components/Storefront.tsx` — спільна шапка, кошик, картки товарів і навігація.
- `src/contexts/StoreContext.tsx` — каталог, міста, кошик і улюблене на frontend.
- `src/pages/PublicPages.tsx` — головна, каталог, інформація про компанію й підтримка.
- `src/pages/AccountPage.tsx` — реєстрація, історія замовлень і квитанції.
- `src/pages/StaffPage.tsx` — робочий простір із ролями, вкладками й управлінням персоналом.
- `src/index.css` — адаптивна тема магазину й кабінетів у стилі прикладу.
- `vite.config.ts` — React-плагін і проксі до Python API під час розробки.
- `catalogs/*.json` — окремий файл даних для кожної категорії.
- `server.py` — вебсервер, API, автентифікація, перевірка ролей та обслуговування `dist/`.
- `PROMETEY_DB_PATH` — шлях до SQLite-бази каталогу, постачальників, працівників, покупців, сеансів і замовлень; типовий локальний шлях — `data/prometey.db`.

Сума замовлення й ціни перевіряються сервером; резерв товару зменшується в межах однієї транзакції. Оформлені замовлення містять вибране місто та автоматично додаються до профілю покупця, якщо він увійшов. Зміни в кабінетах записуються одразу й показуються іншим працівникам під час оновлення даних (до 15 секунд). Історія покупця доступна лише після входу в його обліковий запис. Квитанція підтверджує онлайн-замовлення й не є фіскальним чеком. Оплата демонстраційна: замовлення сплачуються при отриманні, інтеграції платіжного сервісу немає.

## Примітка

Це навчальний проєкт для тестування кошика, а не готова платіжна система. Для використання в інтернеті потрібні HTTPS, постійний диск, резервні копії бази та захищені секрети хостингу. Не використовуйте демонстраційний пароль у публічному середовищі. Каталоги імпортуються в базу під час її першого заповнення; змініть файли `catalogs/` перед першим запуском, якщо хочете замінити початкові товари.

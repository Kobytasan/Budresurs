# «Прометей» — онлайн-магазин і тестовий кошик

Навчальний сайт українського продуктового магазину: React/Vite інтерфейс і Express API на Node.js з Neon/PostgreSQL. Каталог, облікові записи, кошик, замовлення, підтримка та робочі кабінети зберігають дані в онлайн-базі.

## Запуск на Windows

1. Встановіть Node.js.
2. Створіть PostgreSQL базу (наприклад, Neon) та задайте рядок підключення і пароль директора у PowerShell:

   ```powershell
   $env:DATABASE_URL = "ваш рядок підключення PostgreSQL"
   $env:PROMETEY_ADMIN_PASSWORD = "Ваш-надійний-пароль-довжиною-12+"
   ```

3. Відкрийте PowerShell у папці проєкту та встановіть залежності:

   ```powershell
   npm ci
   ```

4. Зберіть і запустіть застосунок:

   ```powershell
   npm run build
   npm start
   ```

5. Відкрийте адресу, яку покаже сервер (типово <http://127.0.0.1:5000>); кабінет команди доступний на `/admin`. Щоб завершити роботу, натисніть `Ctrl+C`.

Для frontend-розробки залиште Node API запущеним командою `npm start`, а в іншому PowerShell запустіть `npm run dev`. Vite відкриє адресу, яку покаже термінал (типово <http://127.0.0.1:5173>) і проксуватиме `/api` до Node-сервера на порт 5000.

Покупці створюють особистий кабінет на сторінці `/account`. Після входу оформлені замовлення зберігаються в історії профілю; для кожного можна переглянути та надрукувати квитанцію або зберегти її у PDF із вікна друку. Гостьове оформлення замовлення також доступне, але такі покупки не прив’язуються до профілю.

Під час першого запуску Node API створює таблиці PostgreSQL, завантажує товари з окремих файлів каталогу в `catalogs/` та створює користувача-директора. Ім’я директора за замовчуванням — `director`, його пароль задається через `PROMETEY_ADMIN_PASSWORD` до першого запуску. Пароль зберігається у вигляді PBKDF2-хешу; зміна змінної середовища не змінить пароль уже створеного директора. Якщо в старій PostgreSQL-базі є покупець лише з номером телефону, зареєструйте кабінет з тим самим номером, щоб додати email і пароль; дані з локальної SQLite-бази до Neon автоматично не переносяться.

Демовхід у Node API вимкнений для публічного хостингу. Для локального середовища можна задати:

```powershell
$env:PROMETEY_DEMO_MODE = "1"
```

## Розгортання на Render

Створіть у Render Web Service з цим Git-репозиторієм. Вкажіть команди:

```text
Build Command: npm ci && npm run build
Start Command: npm start
```

У розділі Environment задайте секрет `DATABASE_URL` (рядок підключення Neon/PostgreSQL), `PROMETEY_ADMIN_PASSWORD` (щонайменше 12 символів), а також:

| Змінна | Значення для хостингу |
|---|---|
| `DATABASE_URL` | Секрет із панелі PostgreSQL/Neon; не додавайте його до Git |
| `PROMETEY_ADMIN_PASSWORD` | Секретний пароль директора (12+ символів), обов’язковий під час першого створення директора |
| `PROMETEY_ADMIN_USERNAME` | Необов’язково; за замовчуванням `director` |
| `PROMETEY_DEMO_MODE` | `0`, щоб вимкнути швидкий демовхід |
| `PROMETEY_COOKIE_SECURE` | `1`, щоб захищені сесійні cookie працювали через HTTPS |

Node API самостійно створює схему й початковий каталог у PostgreSQL. Під час запуску він також приводить товари з однаковою назвою категорії до єдиного slug із файлів каталогу, щоб у списку категорій не було повторів. Після першого розгортання перевірте `https://ваш-сервіс.onrender.com/api/test`, а потім відкрийте `/products`, `/account` і `/admin`. Створений раніше користувач із локальної SQLite-бази не переноситься в Neon автоматично; директорський обліковий запис створюється з заданими змінними середовища. Робочий сервіс не використовує демопрофілі для обходу пароля.

## Ролі та доступ

| Роль | Доступ |
|---|---|
| Директор | Фінанси, товари, працівники, історія статусів, постачальники й звернення підтримки; замовлення з контактами покупців |
| Бухгалтер | Вкладка фінансів, показники, журнал сум і статусів оплати; без контактів покупців, складу чи керування командою |
| Працівник складу | Вкладка товарів, постачальники, залишки й ціни; без фінансів і даних покупців |

Додайте колегу у вкладці працівників кабінету директора: задайте ім’я, логін, посаду й тимчасовий пароль щонайменше з 12 символів. Кожен працівник може самостійно встановити статус «На роботі», «Вихідний», «У відпустці» або «Кінець робочого дня». Директор бачить історію змін і тривалість від останнього початку роботи до завершення дня. Директор може змінити роль або вимкнути/відновити доступ; вимкнення завершує активні сеанси працівника. Система не дозволяє вимкнути останнього директора чи його власний обліковий запис. Директор керує довідником постачальників, а працівники з доступом до товарів можуть обрати постачальника для кожного продукту.

Покупці можуть обрати улюблені товари, які показуються у вкладці «Улюблене» на сторінці `/products`. Список улюбленого та кошик наразі зберігаються у браузері; профілі, замовлення, залишки, постачальники, статуси працівників і звернення підтримки — у серверній базі PostgreSQL. Каталог оновлює залишки приблизно кожні 15 секунд і позначає товари з нульовим залишком як недоступні.

Головна сторінка `/` містить інформацію про магазин. Каталог розміщений на `/products`, інформація про компанію — на `/about`, форма підтримки — на `/support`, кабінет покупця — на `/account`, а кабінет команди — на `/admin`. Місто доставки можна вибрати з переліку Київ, Львів, Одеса, Дніпро, Харків, Вінниця, Черкаси та Полтава; цей перелік є демонстраційним, тому доступність і умови доставки потрібно перевірити для кожного міста окремо. Реальні адресу, телефон і графік компанії не задано, тому сайт не вигадує ці контактні дані.

## Структура

- `src/App.tsx` — маршрути публічних сторінок і кабінету команди.
- `src/components/Storefront.tsx` — спільна шапка, кошик, картки товарів і навігація.
- `src/contexts/StoreContext.tsx` — каталог, міста, кошик і улюблене на frontend.
- `src/pages/PublicPages.tsx` — головна, каталог, інформація про компанію й підтримка.
- `src/pages/AccountPage.tsx` — реєстрація, історія замовлень і квитанції.
- `src/pages/StaffPage.tsx` — робочий простір із ролями, вкладками й управлінням персоналом.
- `src/index.css` — адаптивна тема магазину й кабінетів у стилі прикладу.
- `vite.config.ts` — React-плагін і проксі до Node API під час розробки.
- `catalogs/*.json` — окремий файл даних для кожної категорії.
- `server/server.js` — Express API, автентифікація, перевірка ролей, PostgreSQL і обслуговування `dist/`.
- `server/index.js` — сумісний entrypoint, який запускає основний Node API.
- `DATABASE_URL` — секретний PostgreSQL connection string.
- `PROMETEY_ADMIN_PASSWORD` — пароль директора, що використовується лише під час першого створення облікового запису.

Сума замовлення й ціни перевіряються сервером; резерв товару зменшується в межах однієї транзакції. Оформлені замовлення містять вибране місто та автоматично додаються до профілю покупця, якщо він увійшов. Зміни в кабінетах записуються одразу й показуються іншим працівникам під час оновлення даних (до 15 секунд). Історія покупця доступна лише після входу в його обліковий запис. Квитанція підтверджує онлайн-замовлення й не є фіскальним чеком. Оплата демонстраційна: замовлення сплачуються при отриманні, інтеграції платіжного сервісу немає.

## Примітка

Це навчальний проєкт для тестування кошика, а не готова платіжна система. Для використання в інтернеті потрібні HTTPS, резервні копії PostgreSQL і захищені секрети хостингу. Не використовуйте демонстраційний пароль у публічному середовищі. Відсутні товари з `catalogs/` додаються до PostgreSQL під час запуску сервера; наявні товари й складські залишки не перезаписуються.
